# Website rebuild

The page sells uninterrupted thought through local Mac dictation. Scope is the marketing website only. Keep the static Vite build, real app captures, release manifest, installation limitations, and download fallbacks.

## Direction

An oversized editorial opening leads into a working text destination. Orange voice traces cross a near-black stage. The demonstration inserts a complete transcript only after listening and transcription finish. A quiet, scroll-lit statement separates it from a sticky product walkthrough, an inspectable screenshot gallery, local privacy explanation, setup, and a maker-led footer.

The competing direction was a full-screen desktop throughout. Keep its large text destination and full-width evidence, but use editorial whitespace between product scenes so the page has changing rhythm. The discarded key sculpture is not reused.

## Reference observations

- [ToDesktop](https://vibrant.design/website/cyv6z42-www-todesktop-com) uses a spacious centered opening and large product examples. Adapt the product-first scale, not its pale palette.
- [Neatlogs](https://vibrant.design/website/l4accpy-neatlogs-com) moves from an expansive illustrated opening into close product explanations and recordings. Adapt the change in scale and evidence-led sequence.
- [Natural](https://vibrant.design/website/4ihpu0n-www-natural-com) uses substantial whitespace between large product demonstrations and restrained feature layouts. Adapt the pacing and a substantial closing composition.

The reference scroll recordings were inspected as sampled frames. These establish layout and sequence, not precise easing measurements.

## Data and ownership

HTML owns readable content and working download links. CSS owns composition, sticky behavior, responsive layout, and reduced motion. JavaScript owns one demo state with a sample and phase, the gallery selection, the mobile navigation, and a bounded canvas animation. Samples contain a destination, title, and complete transcript. Phases are idle, listening, transcribing, and complete. No browser microphone is used. A recorded interface walkthrough is explicitly a preview with sample data.

## Delivery gates

1. Build the new page and verify its output and release links. Commit and push.
2. Add the real interface recording and browser checks. Verify replay, cancellation, sample switching, gallery keyboard navigation, FAQ, mobile navigation, reduced motion, missing release metadata, and layout at 320, 390, 768, 1280, and 1440 pixels.
3. Inspect desktop and mobile captures together, correct material issues in one batch, obtain independent review, and push the final verified changes.

The throughput checkpoint is the first working build. It must have a complete readable page and usable downloads before recording polish or secondary motion continues.
